# Lockfile tooling

Reproducibility for the image is two files, both regenerated by the weekly job
(`.github/workflows/weekly-rebuild.yml`) and committed:

| File | Produced by | Consumed by |
|---|---|---|
| `base-digest` | `resolve-base-digest.sh` (skopeo) | `ci/build.sh` → `--build-arg BASE_IMAGE=` |
| `packages.lock` | `make-lock.sh` (`rpm -qa` of a finished image) | `install-packages.sh` inside the Containerfile |

Neither file exists until the first weekly run; without them the build simply
installs the newest packages from the moving base tag. That is the intended
bootstrap path, not an error.

`packages.lock` is a plain `NAME<TAB>EVR<TAB>ARCH` list rather than an
`rpm-lockfile-prototype` YAML on purpose: it needs no extra tooling, diffs
cleanly in review, and doubles as the SBOM diff input for the PATCH-bump rule
in spec §7.4.
